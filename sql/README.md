# HobbyMate SQL 적용 안내

MariaDB 운영 데이터 보호를 위해 SQL 파일은 자동으로 DROP TABLE 또는 데이터를 초기화하지 않는다. 적용 전 백업과 대상 스키마 버전을 확인한다.

## 신규 환경

1. `HobbyMate_MariaDB_DDL_v0.1.sql`
2. `HobbyMate_관리자이력_추가_v0.2.sql`
3. `HobbyMate_서비스정책확장_v0.4.sql`
4. `HobbyMate_모임개설_추가_v0.5.sql` (`IF NOT EXISTS`이므로 v0.4 이후 재확인용으로 실행 가능)

현재 v0.1 기준 DDL에는 임시 본인인증용 회원 컬럼이 이미 포함되어 있다. 따라서 신규 환경에서는 같은 컬럼을 추가하는 v0.3을 실행하지 않는다.

## 기존 환경

- 관리자 이력 테이블만 있고 임시 본인인증 컬럼이 없는 과거 스키마: v0.3 적용 후 v0.4 적용
- 임시 본인인증 기능까지 적용된 현재 스키마: v0.4만 적용
- 모임 개설 기능만 먼저 검증하는 개발 스키마: v0.5를 적용하여 `HM_CLUB.JOIN_GUIDE`만 최소 추가

`HobbyMate_임시본인인증_추가_v0.3.sql`은 과거 스키마용 비파괴 마이그레이션이며 신규 설치용 반복 실행 파일이 아니다.

## v0.4 적용 전 점검

- 같은 모임·회원에 WAITING 가입 신청이 두 건 이상 없는지
- 같은 만남의 모집 게시글이 두 건 이상 없는지
- 같은 회원의 같은 만남 후기가 두 건 이상 없는지
- 같은 신고자의 같은 대상 신고가 두 건 이상 없는지
- 기존 신고 상세 내용이 500자를 초과하지 않는지
- MariaDB 버전이 생성 컬럼, CHECK 제약, InnoDB FULLTEXT를 지원하는지

중복 데이터가 있으면 임의 삭제하지 말고 운영 정책에 따라 정리한 뒤 UNIQUE 제약을 적용한다. v0.4는 기존 상태 코드를 확정 코드로 변환하고 신규 관계·이력 테이블을 생성한다.
