- # HobbyMate DB 테이블 정의서

  > DBMS: MariaDB  
  > 문자셋: `utf8mb4`  
  > 테이블 접두사: `HM_`  
  > 테이블명과 컬럼명은 모두 대문자로 작성한다.

  ## 1. 설계 원칙

  - PK는 `BIGINT UNSIGNED AUTO_INCREMENT`를 사용한다.
  - 모든 테이블은 `InnoDB` 엔진을 사용한다.
  - 날짜·시간은 `DATETIME`을 사용한다.
  - 상태값과 유형값은 영문 대문자 코드로 저장한다.
  - 삭제 데이터는 바로 물리 삭제하지 않고 상태값과 삭제 일시로 관리한다.
  - 회원 탈퇴 시 CI_HASH는 즉시 NULL 처리하고, 30일 후 불필요한 개인정보를 삭제 또는 익명화한다.
  -  로그인 아이디는 탈퇴 후에도 재사용하지 않는다.
  - 닉네임과 이메일은 탈퇴 시 변경하여 재사용 가능하도록 한다.
  - 블로그형 게시글 본문은 `LONGTEXT`에 HTML 형태로 저장한다.
  - 게시글당 이미지 최대 25장 제한은 서비스 계층에서 검증한다.
  - 모임 내부 게시판 접근, 건의·신고 비공개 조회 등 권한은 Spring Security와 서비스 계층에서 검증한다.

  ## 3. 코드값 정의

  ### 3.1 성별

  | 값       | 설명 |
  | -------- | ---- |
  | `FEMALE` | 여성 |
  | `MALE`   | 남성 |

  > `FEMAILE`이 아니라 `FEMALE`이 정확한 표기다.

  ### 3.2 Y/N

  | 값   | 설명                           |
  | ---- | ------------------------------ |
  | `Y`  | 예, 사용, 인증, 활성           |
  | `N`  | 아니오, 미사용, 미인증, 비활성 |

  ### 3.3 회원 권한

  | 값      | 설명          |
  | ------- | ------------- |
  | `USER`        | 일반 회원 |
  | `ADMIN`       | 플랫폼 관리자 |
  | `SUPER_ADMIN` | 최고 관리자 |

  ### 3.4 회원 상태

  | 값          | 설명                                                |
  | ----------- | --------------------------------------------------- |
  | `ACTIVE`    | 정상 이용 중                                        |
  | `SUSPENDED` | 관리자에 의해 이용 정지                             |
  | `PERMANENT_BANNED` | 영구 이용 정지 |
  | `WITHDRAWN` | 회원 탈퇴(CI_HASH 즉시 NULL, 30일 후 불필요 개인정보 익명화) |

  ### 3.4.1 본인인증 방식

  | 값 | 설명 |
  | --- | --- |
  | `ADMIN_TEMP` | 실제 인증 API 연동 전 관리자가 처리한 임시 본인인증 |

  실제 인증기관 코드(`PASS`, `NICE` 등)는 연동 시 추가한다. 관리자 임시 인증 취소는 `ADMIN_TEMP`에만 허용한다.

  ## 4. 테이블 상세

  ### 4.1 `HM_MEMBER`

  | 컬럼명                 | 자료형          | NULL | 기본값            | 설명                                                         |
  | ---------------------- | --------------- | ---: | ----------------- | ------------------------------------------------------------ |
  | `MEMBER_ID`            | BIGINT UNSIGNED |    N | AUTO_INCREMENT    | 회원 PK                                                      |
  | `LOGIN_ID`             | VARCHAR(50)     |    N |                   | 일반 로그인 아이디, UNIQUE                                   |
  | `PASSWORD`             | VARCHAR(255)    |    N |                   | 암호화 비밀번호                                              |
  | `NAME`                 | VARCHAR(50)     |    Y | NULL              | 본인인증 이름(탈퇴 30일 후 익명화 가능)                      |
  | `NICKNAME`             | VARCHAR(50)     |    N |                   | 닉네임, UNIQUE                                               |
  | `EMAIL`                | VARCHAR(255)    |    N |                   | 이메일, UNIQUE                                               |
  | `PHONE`                | VARCHAR(30)     |    Y | NULL              | 본인인증 휴대폰 번호(탈퇴 30일 후 익명화 가능)               |
  | `BIRTH_DATE`           | DATE            |    Y | NULL              | 본인인증 생년월일(탈퇴 30일 후 익명화 가능)                  |
  | `GENDER`               | VARCHAR(10)     |    Y | NULL              | `FEMALE`, `MALE`                                             |
  | `IDENTITY_VERIFIED_YN` | CHAR(1)         |    N | `N`               | 본인인증 여부                                                |
  | `IDENTITY_VERIFICATION_METHOD` | VARCHAR(30) | Y | NULL | 본인인증 방식, 관리자 임시는 `ADMIN_TEMP` |
  | `IDENTITY_VERIFIED_AT` | DATETIME        |    Y | NULL              | 본인인증 완료 일시                                           |
  | `IDENTITY_VERIFIED_BY` | BIGINT UNSIGNED | Y | NULL | 임시 본인인증 처리 관리자 회원 FK |
  | `IDENTITY_VERIFICATION_REASON` | VARCHAR(2000) | Y | NULL | 임시 본인인증 처리 사유 |
  | `CI_HASH`              | VARCHAR(255)    |    Y | NULL              | 중복가입 확인용 CI 해시(회원 탈퇴 시 NULL 처리)              |
  | `PROFILE_IMAGE_URL`    | VARCHAR(1000)   |    Y | NULL              | 프로필 이미지 UUID 저장 파일명(전체 경로·URL 저장 금지)      |
  | `PROFILE_THUMBNAIL_URL` | VARCHAR(1000)  |    Y | NULL              | 200×200 프로필 썸네일 저장 키                                |
  | `MEMBER_ROLE`          | VARCHAR(20)     |    N | `USER`            | `USER`, `ADMIN`, `SUPER_ADMIN`                               |
  | `MEMBER_STATUS`        | VARCHAR(20)     |    N | `ACTIVE`          | `ACTIVE`, `SUSPENDED`, `PERMANENT_BANNED`, `WITHDRAWN`       |
  | `WITHDRAWN_AT`         | DATETIME        |    Y | NULL              | 탈퇴 일시                                                    |
  | `PERSONAL_INFO_PURGED_AT` | DATETIME     |    Y | NULL              | 탈퇴 30일 후 개인정보 삭제·익명화 일시                       |
  | `CREATED_AT`           | DATETIME        |    N | CURRENT_TIMESTAMP | 등록 일시                                                    |
  | `UPDATED_AT`           | DATETIME        |    N | CURRENT_TIMESTAMP | 수정 일시                                                    |
  | `UPDATED_BY`           | BIGINT UNSIGNED | Y | NULL | 최종 수정 관리자 회원 FK |

  관리자 임시 인증의 `CI_HASH`는 `TEMP-{MEMBER_ID}-{UUID}` 형식으로 서버에서 생성한다. `IDENTITY_VERIFIED_BY`와 `UPDATED_BY`는 `HM_MEMBER.MEMBER_ID`를 참조한다.

  #### 회원 탈퇴 정책

  회원 탈퇴 시 회원 데이터는 삭제하지 않는다.

  | 항목          | 처리 방식                           |
  | ------------- | ----------------------------------- |
  | LOGIN_ID      | 유지 (재사용 불가)                  |
  | PASSWORD      | 유지                                |
  | NAME          | 30일 보관 후 삭제 또는 익명화       |
  | PHONE         | 30일 보관 후 삭제 또는 익명화       |
  | BIRTH_DATE    | 30일 보관 후 삭제 또는 익명화       |
  | GENDER        | 30일 보관 후 삭제 또는 익명화       |
  | CI_HASH       | NULL 처리                           |
  | NICKNAME      | 탈퇴회원{MEMBER_ID}                 |
  | EMAIL         | deleted_{MEMBER_ID}@hobbymate.local |
  | MEMBER_STATUS | WITHDRAWN                           |
  | WITHDRAWN_AT  | 탈퇴 일시 저장                      |

  재가입 시에는 기존 회원을 복구하지 않고 새로운 MEMBER_ID를 발급한다.

  #### 프로필 이미지 저장 정책

  - `PROFILE_IMAGE_URL`은 기존 컬럼명을 유지하되 값은 `UUID.확장자` 형식의 서버 저장 파일명만 기록한다.
  - 원본 파일명, 서버 절대 경로, Context Path 및 전체 URL은 기록하지 않는다.
  - 프로필 이미지가 없거나 삭제된 경우 `NULL`로 관리하며 기본 이미지 경로를 회원 행에 저장하지 않는다.
  - 허용 확장자는 `jpg`, `jpeg`, `png`, `webp`이며 파일 자체는 외부 파일 시스템에 저장한다.
  - 회원 탈퇴 시 현재 정책에 따라 컬럼 값과 실제 파일을 유지한다.

  | `TITLE`            | VARCHAR(300)    |    N |                   | 제목                                        |
  | `CONTENT`          | LONGTEXT        |    N |                   | 블로그형 HTML 본문                          |
  | `VIEW_COUNT`       | BIGINT UNSIGNED |    N | `0`               | 조회수                                      |
  | `NOTICE_YN`        | CHAR(1)         |    N | `N`               | 동일 모임·게시판 내 상단 고정 여부 (`Y`, `N`) |
  | `POST_STATUS`      | VARCHAR(20)     |    N | `ACTIVE`          | 게시글 상태                                 |
  | `CREATED_AT`       | DATETIME        |    N | CURRENT_TIMESTAMP | 등록 일시                                   |
  | `UPDATED_AT`       | DATETIME        |    N | CURRENT_TIMESTAMP | 수정 일시                                   |

  - `NOTICE_YN`은 공지 전용 별도 테이블이 아닌 공통 모임 게시글 컬럼이다. 동일 `CLUB_ID`와 `POST_TYPE` 범위에서 `ACTIVE`이면서 미삭제인 글을 고정 대상으로 계산한다.
  - 상단 고정은 `NOTICE`, 향후 `FREE`, `REVIEW`에서 공통 사용하며 자동 생성·일정 중심인 `MEETING`은 초기 대상에서 제외한다.
  - 상단 고정은 게시판별 최대 5개로 제한한다. 역할·개수 제한은 `ACTIVE` 모임장·운영진을 검증하는 서비스 트랜잭션에서 보장하고, `NOTICE_YN` 자체는 `Y/N` CHECK와 `N` 기본값을 사용한다.
  - 공지 작성 화면은 DB 제목 길이 300자보다 엄격한 2~200자, 내용은 10~10,000자의 일반 텍스트로 검증한다. 게시글 유형, 작성자, 상태, 조회수와 일시는 서버가 지정한다.
  - 공지 상세는 `CLUB_ID + CLUB_POST_ID + POST_TYPE = NOTICE + POST_STATUS = ACTIVE + DELETED_AT IS NULL`을 함께 조건으로 조회한다. 정상 접근 시 `VIEW_COUNT = VIEW_COUNT + 1`로 원자 증가시키고 조회 수 변경만으로 `UPDATED_AT`은 변경하지 않는다.
  - 공지의 이전·다음 글은 동일 모임·동일 `NOTICE` 유형의 정상·미삭제 글에서 `CREATED_AT`, `CLUB_POST_ID` 기준으로 조회한다. 목록의 고정 우선 정렬이나 검색 조건은 인접 글 판단에 사용하지 않는다.

  `TARGET_ID`는 여러 종류의 테이블 PK를 가리키므로 물리 FK를 설정하지 않는다. `TARGET_TYPE`과 `TARGET_ID`의 실제 유효성은 서비스 계층에서 검증한다.

  ### 4.17 `HM_ADMIN_ACTION_HISTORY`

  플랫폼 관리자가 회원, 모임, 게시글, 댓글, 신고, 건의 등에 수행한 주요 처리 내역을 기록하는 감사 이력 테이블이다.

  각 업무 테이블에는 현재 상태를 저장하고, 이 테이블에는 관리자가 **누구에게, 언제, 어떤 작업을, 어떤 사유로 수행했는지**를 기록한다.

  | 컬럼명                    | 자료형          | NULL | 기본값            | 설명                         |
  | ------------------------- | --------------- | ---: | ----------------- | ---------------------------- |
  | `ADMIN_ACTION_HISTORY_ID` | BIGINT UNSIGNED |    N | AUTO_INCREMENT    | 관리자 처리 이력 PK          |
  | `ADMIN_MEMBER_ID`         | BIGINT UNSIGNED |    N |                   | 작업을 수행한 관리자 회원 FK |
  | `TARGET_TYPE`             | VARCHAR(30)     |    N |                   | 처리 대상 유형               |
  | `TARGET_ID`               | BIGINT UNSIGNED |    N |                   | 처리 대상 데이터의 PK 값     |
  | `ACTION_TYPE`             | VARCHAR(30)     |    N |                   | 관리자 처리 유형             |
  | `ACTION_REASON`           | VARCHAR(2000)   |    Y | NULL              | 처리 사유                    |
  | `BEFORE_STATUS`           | VARCHAR(50)     |    Y | NULL              | 처리 전 상태값               |
  | `AFTER_STATUS`            | VARCHAR(50)     |    Y | NULL              | 처리 후 상태값               |
  | `ACTION_RESULT`           | VARCHAR(20)     |    N | `SUCCESS`         | 처리 결과                    |
  | `RESULT_MESSAGE`          | VARCHAR(2000)   |    Y | NULL              | 처리 결과 또는 참고 메모     |
  | `BEFORE_VERIFICATION_METHOD` | VARCHAR(30) | Y | NULL | 처리 전 본인인증 방식 |
  | `AFTER_VERIFICATION_METHOD` | VARCHAR(30) | Y | NULL | 처리 후 본인인증 방식 |
  | `BEFORE_CI_HASH` | VARCHAR(255) | Y | NULL | 처리 전 CI 해시, 화면·로그 노출 금지 |
  | `AFTER_CI_HASH` | VARCHAR(255) | Y | NULL | 처리 후 CI 해시, 화면·로그 노출 금지 |
  | `PROCESSING_TYPE` | VARCHAR(20) | Y | NULL | `INDIVIDUAL`, `BATCH` |
  | `OPERATION_ID` | VARCHAR(36) | Y | NULL | 동일 요청을 식별하는 UUID |
  | `CREATED_AT`              | DATETIME        |    N | CURRENT_TIMESTAMP | 처리 일시                    |

  #### `TARGET_TYPE` 코드값

  | --------------- | ------------------ |
  | `MEMBER`        | 회원               |
  | `CLUB`          | 모임               |

  | `REPORT`        | 신고               |
  | `SUGGESTION`    | 건의               |
  | `CATEGORY`      | 취미 카테고리      |

  #### `ACTION_TYPE` 코드값

  | 값          | 설명                       |
  | ----------- | -------------------------- |
  | `SUSPEND`   | 회원 이용 정지             |
  | `UNSUSPEND` | 회원 이용 정지 해제        |
  | `BLOCK`     | 모임·만남·게시글·댓글 차단 |
  | `UNBLOCK`   | 차단 해제                  |

  | 값         | 설명           |
  | ---------- | -------------- |
  | `SUCCESS`  | 정상 처리 완료 |
  | `FAIL`     | 처리 실패      |
  | `CANCELED` | 처리 취소      |

  #### 관계 및 제약조건

  - `ADMIN_MEMBER_ID`는 `HM_MEMBER.MEMBER_ID`를 참조한다.
  - 실제 관리자 여부는 `HM_MEMBER.MEMBER_ROLE = 'ADMIN'`인지 서비스 계층에서 검증한다.
  - `TARGET_ID`는 여러 테이블의 PK를 가리키므로 물리 FK를 설정하지 않는다.
  - `TARGET_TYPE`과 `TARGET_ID` 조합의 유효성은 서비스 계층에서 검증한다.
  - 관리자 작업 대상의 상태 변경과 이력 저장은 하나의 트랜잭션으로 처리한다.
  - 감사 목적의 이력 데이터이므로 일반 수정·삭제 기능을 제공하지 않는다.
  - 이력 조회는 관리자 권한이 있는 사용자만 가능하다.
  - 임시 본인인증 처리와 취소는 회원 상태 변경과 같은 트랜잭션으로 기록하며, 일괄 작업은 동일한 `OPERATION_ID`를 사용한다.
  - 이력의 CI 값은 감사 목적 DB 데이터로만 보관하고 화면과 일반 애플리케이션 로그에 출력하지 않는다.

  #### 처리 예시

  회원 이용 정지:

  ```text
  ADMIN_MEMBER_ID = 1
  TARGET_TYPE = MEMBER
  TARGET_ID = 25
  ACTION_TYPE = SUSPEND
  ACTION_REASON = 반복적인 욕설 신고 누적
  BEFORE_STATUS = ACTIVE
  AFTER_STATUS = SUSPENDED
  ACTION_RESULT = SUCCESS
  ```

  ## 6. 서비스 계층 검증 규칙

  1. 본인인증 완료 회원만 모임에 가입할 수 있다.
  2. 모임 가입 시 회원 성별과 `GENDER_POLICY`를 비교한다.
  3. `BIRTH_DATE`를 기준으로 만 나이를 계산하여 `MIN_AGE`, `MAX_AGE`를 검증한다.
  4. 현재 활동 회원 수와 `MAX_MEMBER_COUNT`를 트랜잭션 안에서 검증한다.
  5. 모임 가입자만 모임 내부 게시판에 접근할 수 있다.
  6. 모임장·운영진만 가입 신청을 승인 또는 거절한다.
  7. 만남 정원 내 신청은 즉시 확정하고 초과 신청은 대기 순번으로 등록하며, 확정 인원이 정원을 넘지 않도록 동시성 검증한다.
  8. `OFFLINE` 만남은 장소·주소·위도·경도가 필수다.
  9. `ONLINE` 만남은 화상회의 플랫폼과 참여 링크가 필수다.
  10. 온라인 참여 링크는 해당 만남 참여자에게만 노출한다.
  11. 만남 후기 작성자를 실제 참석자(`ATTENDED`)로 제한할 수 있다.
  12. 게시글당 사용 중인 이미지는 최대 25장이다.
  13. 오래된 `TEMP` 이미지는 배치 작업으로 삭제한다.
  14. 건의와 신고는 작성자 본인 및 관리자만 조회할 수 있다.
  15. 공지사항 작성·수정·삭제는 관리자만 가능하다.
  16. 회원 정지, 모임 차단, 게시글·댓글 차단/복원, 신고·건의 처리 등 주요 관리자 작업은 `HM_ADMIN_ACTION_HISTORY`에 기록한다.
  17. 관리자 대상 데이터 변경과 이력 저장은 같은 트랜잭션으로 처리한다.
  18. 동일한 CI_HASH를 가진 ACTIVE 회원이 존재하면 회원가입을 제한한다.
  19. WITHDRAWN 회원은 CI_HASH가 NULL이므로 새 MEMBER_ID로 즉시 재가입할 수 있다.
  20. 탈퇴 회원의 LOGIN_ID는 재사용할 수 없다.
  21. 탈퇴 회원의 NICKNAME과 EMAIL은 재사용할 수 있다.

  ## 7. 개인정보·보안 주의사항

  - 주민등록번호는 저장하지 않는다.
  - 휴대폰 번호는 암호화하여 저장하고 화면에는 마스킹하며, 탈퇴 30일 후 법적 보관 필요가 없으면 삭제 또는 익명화한다.
  - CI 원문은 저장하지 않는다. CI_HASH만 저장하며 회원 탈퇴 시 NULL 처리한다.

  - 비밀번호는 BCrypt 등 단방향 해시로 저장한다.
  - 화상회의 링크와 비밀번호는 권한 검증 후 응답한다.
  - HTML 본문은 XSS 방지를 위해 허용 태그 기준으로 정제한다.

  ### 8.3 핵심 상태와 저장 규칙

  - 모임 회원 이벤트는 `JOIN`, `LEFT`, `KICKED`, `ROLE_CHANGED`, `LEADER_TRANSFER`, `CLUB_CLOSED`다. `REJOIN_AVAILABLE_AT`으로 12시간 제한을 표현한다.
  - 만남 대기는 같은 `HM_MEETING_PARTICIPANT` 행에서 관리한다. `OFFER_RESPONSE`는 `ACCEPTED`, `DECLINED`, `EXPIRED`이며 미응답 만료는 노쇼가 아니다.
  - `HM_CLUB_POST.MEETING_RECRUIT_KEY`는 MEETING 글에서만 만남 ID를 반환하여 만남별 모집글 하나를 보장한다. `REVIEW_AUTHOR_KEY`는 REVIEW 글에서만 작성자를 반환하여 회원·만남별 후기 하나를 보장한다.
  - 알림은 `READ/UNREAD`, `NORMAL/IMPORTANT`, 액션 `NONE/PENDING/ACCEPTED/DECLINED/EXPIRED`를 사용하고 `EXPIRES_AT`으로 90일 보관한다.
  - 신고 대상은 다형 관계여서 물리 FK를 두지 않는다. 사유는 `SPAM_AD`, `ABUSE_DEFAMATION`, `SEXUAL_CONTENT`, `HATE_DISCRIMINATION`, `FRAUD_FALSE_INFORMATION`, `ILLEGAL_ACTIVITY`, `CLUB_RULE_VIOLATION`, `OTHER`다.
  - 회원 제재는 `WARNING`, `SUSPENSION`, `PERMANENT_BAN`, `REPORT_RESTRICTION`; 상태는 `ACTIVE`, `EXPIRED`, `REVOKED`다.
  - 이미지에는 서버 절대 경로를 저장하지 않는다. 허용 형식, 25장·장당 10MB·글 전체 100MB는 서비스에서 검증한다.

  | 동일 대상 신고 | `(REPORTER_MEMBER_ID,TARGET_TYPE,TARGET_ID)` UNIQUE |

  | 모임 즐겨찾기 | `(MEMBER_ID,CLUB_ID)` UNIQUE |

  운영진 최대 5명, 모임장 보유 최대 5개, 가입·정원·성별·연령, 시작 10분 전 취소, OTHER 상세 필수, 다형 대상 존재 여부는 서비스 트랜잭션에서 잠금 후 재검증한다.

  ### 8.5 탈퇴와 개인정보

  | 시점 | 처리 |
  |---|---|
  | 탈퇴 즉시 | `WITHDRAWN`, 탈퇴일, `CI_HASH=NULL`, 닉네임·이메일 익명화, 인증·세션 종료 |
  | 30일 보관 | 법적·운영상 필요한 이력과 분쟁 대응 정보만 제한 접근 |
  | 30일 경과 | 불필요한 이름·전화·생년월일·성별 삭제/익명화, `PERSONAL_INFO_PURGED_AT` 기록 |

  로그인 아이디는 재사용 방지를 위해 보존한다. 콘텐츠와 FK는 보존하지만 일반 화면에는 `탈퇴한 회원`으로 표시한다. 로그인 이력은 회원 화면 최근 30건만 제공하고 원시 IP 등은 관리자에게만 제공한다.
