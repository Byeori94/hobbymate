# 1. 프로젝트 개요

## 1.1 프로젝트명

**HobbyMate**

## 1.2 프로젝트 소개

HobbyMate는 공통의 취미를 가진 사람들이 쉽고 안전하게 모임을 만들고, 온·오프라인 활동을 함께할 수 있도록 지원하는 취미 기반 커뮤니티 플랫폼이다.

단순한 게시판이나 오픈채팅 기반의 모임이 아닌,

- 안전한 본인인증
- 체계적인 모임 관리
- 다양한 게시판
- 정기 만남
- 관리자 기능

등을 제공하여 신뢰성 있는 취미 커뮤니티를 만드는 것을 목표로 한다.

---

# 2. 서비스 목표

HobbyMate는 다음과 같은 문제를 해결하는 것을 목표로 한다.

- 신뢰할 수 없는 익명 모임 문제
- 성별 및 연령 제한이 어려운 기존 커뮤니티
- 게시판과 모임 기능이 분리되어 있는 서비스
- 만남 관리 기능 부족
- 모임 운영자의 관리 기능 부족

이를 해결하기 위해

- 본인인증 기반 회원관리
- 모임 중심 커뮤니티
- 게시판과 만남 기능 통합
- 관리자 중심 신고 처리

기능을 제공한다.

# 4. 회원

## 4.1 회원가입

회원가입은 일반 회원가입을 기본으로 제공한다.

향후 카카오 로그인을 추가할 수 있도록 구조를 설계한다.

회원가입 시 반드시 휴대폰 본인인증을 완료해야 한다.

본인인증을 완료하지 않은 사용자는 회원가입을 진행할 수 없다.

---

## 4.2 회원가입 절차

```text
회원가입

↓

아이디 입력

↓

닉네임 입력

↓

비밀번호 입력

↓

휴대폰 본인인증

↓

회원가입 완료
```

---

## 4.3 회원가입 정보

회원가입 시 저장되는 정보

- 로그인 아이디
- 비밀번호(BCrypt 암호화)
- 이름
- 닉네임
- 이메일
- 휴대폰 번호
- 생년월일
- 성별
- 본인인증 CI Hash

---

## 4.4 본인인증

휴대폰 본인인증을 통해 다음 정보를 획득한다.

- 이름
- 생년월일
- 성별
- 휴대폰번호
- 본인 식별 CI

획득한 CI는 SHA-256 등 단방향 해시 후 저장한다.

원본 CI는 저장하지 않는다.

---

## 4.5 로그인

초기 버전은 아이디와 비밀번호를 이용한 일반 로그인을 제공한다.

인증은 Spring Security 기반의 세션 방식으로 처리하며, 비밀번호는 회원가입 시 저장한 BCrypt 해시로 검증한다.

`ACTIVE` 상태 회원만 로그인할 수 있다. 탈퇴 또는 이용 정지 회원, 존재하지 않는 아이디, 잘못된 비밀번호는 모두 다음 통합 메시지로 안내한다.

```text
아이디 또는 비밀번호가 올바르지 않습니다.
```

인증이 필요한 페이지에서 로그인 화면으로 이동한 경우 Saved Request에 저장된 원래 페이지로 복귀하고, 원래 요청이 없으면 메인 페이지 `/`로 이동한다.

아이디 저장 기능은 `hobbymate_saved_id` 쿠키에 아이디만 30일 동안 보관한다. 비밀번호, 인증 정보, 권한, 세션 ID 또는 인증 토큰은 저장하지 않는다. 쿠키 경로는 현재 Context Path를 기준으로 설정하며 서버에서 읽어 화면에 전달한다.

로그인 상태 유지(Remember-me)는 지원하지 않으며 세션 만료 시간은 60분이다.

로그아웃은 CSRF 토큰이 포함된 `POST /auth/logout` 요청으로만 처리한다. 인증 정보를 제거하고 세션을 무효화하되 아이디 저장 쿠키는 유지한다.

---

## 4.6 카카오 로그인

초기 버전에서는 구현하지 않는다.

향후 기능 추가 시

- 카카오 로그인
- 카카오 회원가입

을 지원한다.

카카오 로그인 사용자의 경우에도 휴대폰 본인인증을 수행하여 동일한 회원 정책을 적용한다.

---

## 4.7 회원 권한

회원 권한은 다음과 같다.

| 권한  | 설명      |
| ----- | --------- |
| USER  | 일반 회원 |
| ADMIN | 관리자    |

일반 회원에게는 `ROLE_USER`를 부여한다. 관리자는 일반 회원 기능도 이용할 수 있도록 `ROLE_USER`와 `ROLE_ADMIN`을 함께 부여한다.

---

## 4.8 회원 상태

회원 상태는 다음과 같다.

| 상태      | 설명             |
| --------- | ---------------- |
| ACTIVE    | 정상 이용        |
| SUSPENDED | 관리자 이용 정지 |
| PERMANENT_BANNED | 영구 이용 정지 |
| WITHDRAWN | 회원 탈퇴        |

---

## 4.9 회원 탈퇴 정책

회원 탈퇴 시 회원 데이터를 물리 삭제하지 않는다.

탈퇴 회원의 데이터는 관리자 감사 및 운영 기록을 위해 보관한다.

회원 탈퇴 시 다음과 같이 처리한다.

| 항목          | 처리 방법                                  |
| ------------- | ------------------------------------------ |
| LOGIN_ID      | 유지                                       |
| PASSWORD      | 유지                                       |
| NAME          | 30일 보관 후 삭제 또는 익명화              |
| PHONE         | 30일 보관 후 삭제 또는 익명화              |
| BIRTH_DATE    | 30일 보관 후 삭제 또는 익명화              |
| GENDER        | 30일 보관 후 삭제 또는 익명화              |
| CI_HASH       | NULL 처리                                  |
| NICKNAME      | 탈퇴회원{회원번호}로 변경                  |
| EMAIL         | deleted_{회원번호}@hobbymate.local 로 변경 |
| MEMBER_STATUS | WITHDRAWN 변경                             |
| WITHDRAWN_AT  | 탈퇴 시각 저장                             |

---

## 4.10 재가입 정책

회원 탈퇴 후 즉시 재가입할 수 있다.

재가입 시에는 기존 회원 정보를 복구하지 않고 새로운 회원으로 가입한다.

따라서

- 새로운 MEMBER_ID가 생성된다.
- 기존 아이디는 사용할 수 없다.
- 기존 닉네임은 사용할 수 있다.
- 기존 이메일은 사용할 수 있다.

관리자에 의해 이용 정지된 회원은 서비스 정책에 따라 재가입이 제한될 수 있다.

---

## 4.11 중복가입 정책

회원가입 시 인인증을 통해 획득한 CI Hash를 이용하여 동일인 여부를 확인한다.

동일한 CI Hash를 가진 ACTIVE 회원이 존재할 경우 회원가입을 제한한다.

WITHDRAWN 회원은 CI Hash를 NULL 처리하므로 새로운 회원으로 가입할 수 있다.

---

## 4.12 개인정보 보호

회원 개인정보는 최소한으로 저장한다.

비밀번호는 BCrypt로 암호화하여 저장한다.

CI는 해시값만 저장한다.

휴대폰 번호는 탈퇴 후 30일 동안 보관하고, 법적·운영상 보관 필요가 없으면 삭제 또는 익명화한다.

이메일과 닉네임은 탈퇴 시 변경하여 재사용이 가능하도록 한다.

관리자는 개인정보를 최소한으로 조회할 수 있도록 한다.

---

## 4.13 마이페이지

마이페이지는 로그인한 `ACTIVE` 회원과 관리자만 접근할 수 있으며, 내부 URL은 `GET /member/mypage`를 사용한다. 비로그인 사용자는 Spring Security 로그인 화면으로 이동하고 로그인 성공 후 Saved Request에 따라 마이페이지로 복귀한다.

조회 대상은 URL 파라미터나 hidden input으로 지정하지 않고 Spring Security 인증 객체의 회원 번호로 식별한다. 회원은 현재 로그인한 자신의 정보만 조회할 수 있다.

마이페이지에는 다음 기본정보만 표시한다.

- 프로필 이미지
- 닉네임
- 로그인 아이디
- 이름
- 이메일
- 휴대폰 번호
- 성별
- 생년월일
- 가입일

휴대폰 번호는 가운데 번호를 마스킹하여 표시하고, 생년월일과 가입일은 `yyyy.MM.dd` 형식으로 표시한다. 비밀번호, CI, 탈퇴 여부, 관리자 여부 등의 민감정보와 내부 운영정보는 조회 결과 및 화면에 포함하지 않는다.

프로필 이미지가 등록되지 않은 경우 기본 프로필 이미지를 사용한다. 로그인 아이디는 본인 마이페이지에서만 기본정보로 표시하며, 헤더·게시글 작성자·댓글 작성자·모임 회원명처럼 다른 회원에게 노출되는 영역에서는 닉네임을 사용한다.

활동 내역은 후속 개발 범위로 둔다.

운영 환경의 `/hobbymate`는 Context Path로 적용하며 컨트롤러, Spring Security, 템플릿 및 정적 리소스 내부 URL에 직접 하드코딩하지 않는다.

## 4.14 회원정보 수정

회원정보 수정은 로그인한 `ACTIVE` 회원과 관리자만 이용할 수 있으며, 내부 URL은 `GET /member/mypage/edit`과 `POST /member/mypage/edit`을 사용한다. 수정 대상은 URL 파라미터나 hidden input으로 지정하지 않고 Spring Security 인증 객체의 회원 번호로 식별하므로 현재 로그인한 본인의 정보만 수정할 수 있다.

회원이 직접 수정할 수 있는 항목은 닉네임과 이메일로 제한한다. 로그인 아이디, 이름, 휴대폰 번호, 성별, 생년월일은 변경할 수 없으며 수정 화면에서는 조회 정보로만 표시한다. 휴대폰 번호는 가운데 번호를 마스킹하고, 휴대폰 번호 변경은 추후 본인인증을 다시 수행하는 별도 기능으로 제공한다. 비밀번호와 CI는 수정 화면 및 요청 객체에 포함하지 않는다.

닉네임은 회원가입과 동일하게 앞뒤 공백을 제거한 필수값으로 최대 50자까지 허용한다. 다른 닉네임으로 변경하는 경우 중복확인을 진행하고, 저장 시 서버가 현재 회원 자신을 제외하여 다시 중복 여부를 검사한다. 현재 닉네임을 유지하는 경우에는 중복확인을 요구하지 않는다. 탈퇴 회원은 탈퇴 처리 시 닉네임이 대체되므로 기존 닉네임을 재사용할 수 있다.

이메일은 앞뒤 공백을 제거하고 소문자로 정규화하며 필수값·형식·최대 255자를 서버에서 검증한다. 이메일 중복확인 UI와 API는 제공하지 않는다.

수정 SQL은 `NICKNAME`, `EMAIL`만 변경하고 `MEMBER_ID` 및 `MEMBER_STATUS = 'ACTIVE'` 조건을 적용한다. 수정일시는 `UPDATED_AT`의 기존 자동 갱신 정책을 따른다. 수정 성공 후 현재 Spring Security 인증 객체의 닉네임을 즉시 갱신하여 재로그인 없이 공통 헤더에 반영하고, Flash Attribute로 성공 메시지를 한 번 표시한다.

운영 환경의 `/hobbymate`는 Context Path로 적용하며 내부 URL에 직접 하드코딩하지 않는다.

## 4.15 비밀번호 변경

비밀번호 변경은 로그인한 `ACTIVE` 회원과 관리자만 이용할 수 있으며, 내부 URL은 `GET /member/mypage/password`와 `POST /member/mypage/password`를 사용한다. 변경 대상은 URL 파라미터나 hidden input으로 지정하지 않고 Spring Security 인증 객체의 회원 번호로 식별하므로 현재 로그인한 본인의 비밀번호만 변경할 수 있다.

현재 비밀번호, 새 비밀번호, 새 비밀번호 확인은 모두 필수다. 현재 비밀번호는 DB의 최신 BCrypt 해시와 `PasswordEncoder.matches()`로 비교하고, 새 비밀번호와 확인값의 일치 여부를 서버에서 다시 검증한다. 새 비밀번호는 회원가입과 동일하게 8~255자, 공백 없이 영문·숫자·특수문자 중 2종 이상을 사용해야 하며 서버가 값을 임의로 trim하지 않는다.

새 비밀번호는 DB의 기존 해시와 `PasswordEncoder.matches()`로 비교하여 현재 비밀번호와 같은 값의 재사용을 차단한다. 모든 검증을 통과한 경우에만 `PasswordEncoder.encode()`로 한 번 암호화하여 `PASSWORD` 컬럼만 수정한다. `UPDATED_AT`은 DB의 기존 자동 갱신 정책을 따르며 로그인 아이디, 닉네임, 이메일, 권한 및 다른 회원정보는 변경하지 않는다.

변경 성공 후 마이페이지로 이동하여 Flash Attribute 성공 메시지를 한 번 표시하고, 현재 세션과 `ROLE_USER`·`ROLE_ADMIN` 권한은 유지한다. 다른 기기 세션 종료와 전체 기기 로그아웃, 비밀번호 찾기 및 재설정은 후속 개발 범위로 둔다.

비밀번호 평문과 해시는 로그, Model, Flash Attribute, URL 및 브라우저 저장소에 노출하지 않는다. POST 요청의 CSRF 보호를 유지하고 운영 환경의 `/hobbymate`는 Context Path로 적용하여 내부 URL에 직접 하드코딩하지 않는다.

## 4.16 회원 탈퇴 기능

회원 탈퇴는 로그인한 `ACTIVE` 회원과 관리자만 이용할 수 있으며, 내부 URL은 `GET /member/mypage/withdraw`와 `POST /member/mypage/withdraw`를 사용한다. 탈퇴 대상은 URL 파라미터나 hidden input으로 지정하지 않고 Spring Security 인증 객체의 회원 번호로 식별하므로 현재 로그인한 본인의 계정만 탈퇴할 수 있다.

현재 비밀번호와 탈퇴 동의는 필수다. 서버는 DB의 최신 BCrypt 해시와 `PasswordEncoder.matches()`로 현재 비밀번호를 검증하고, 동의값이 `true`인지 다시 확인한다. POST 요청에는 CSRF 보호를 유지하며 비밀번호는 trim하거나 로그, Model, Flash Attribute, URL 및 브라우저 저장소에 노출하지 않는다.

탈퇴는 회원 행을 삭제하지 않는 Soft Delete 방식으로 하나의 트랜잭션에서 처리한다. `MEMBER_STATUS`를 `WITHDRAWN`으로 변경하고 `WITHDRAWN_AT`에 탈퇴 시각을 저장하며 `CI_HASH`는 NULL 처리한다. 닉네임은 `탈퇴회원{MEMBER_ID}`, 이메일은 `deleted_{MEMBER_ID}@hobbymate.local`로 변경하여 기존 닉네임과 이메일을 재사용할 수 있게 한다. 로그인 아이디와 비밀번호, 이름, 휴대폰 번호, 생년월일, 성별 및 프로필 이미지 경로는 유지한다.

회원 탈퇴 시 게시글과 댓글, 프로필 이미지 파일은 삭제하거나 수정하지 않는다. 현재 스키마에는 본인 탈퇴용 회원 이력 테이블이 없고 `HM_ADMIN_ACTION_HISTORY`는 관리자 처리 전용이므로 별도 탈퇴 이력을 저장하지 않는다.

DB UPDATE가 정확히 1건 완료된 뒤에만 Spring Security 인증 정보를 제거하고 기존 HTTP Session을 무효화한다. 이후 비로그인 메인 화면 `/`로 이동하며 새 익명 세션의 Flash Attribute로 `회원 탈퇴가 완료되었습니다.` 메시지를 한 번 표시한다. 운영 환경의 `/hobbymate`는 Context Path로 적용하고 내부 URL에 직접 하드코딩하지 않는다.

---

## 4.17 프로필 사진 관리

프로필 사진 등록·변경·삭제는 로그인한 `ACTIVE` 회원과 관리자만 이용할 수 있다. 대상 회원은 URL 파라미터나 hidden input으로 받지 않고 Spring Security 인증 객체의 회원 번호로 식별한다.

등록과 변경은 `POST /member/mypage/profile-image`, 삭제는 `POST /member/mypage/profile-image/delete`를 사용하며 두 요청 모두 CSRF 보호를 유지한다. 업로드 화면에서는 선택 이미지 미리보기와 중복 제출 방지를 제공한다.

프로필 이미지는 프로젝트 소스 및 정적 리소스와 분리된 외부 파일 시스템에 저장한다. 개발 기본 경로는 `uploads/profile`이고 `app.upload.profile-dir` 설정으로 운영 절대 경로로 교체할 수 있다. DB의 `PROFILE_IMAGE_URL`에는 전체 경로나 URL, 원본 파일명이 아닌 UUID 기반 저장 파일명만 기록한다. 미등록 상태는 `NULL`로 유지하며 화면에서는 `images/common/default-profile.png`를 사용한다.

허용 형식은 JPG, JPEG, PNG, WEBP이며 최대 크기는 5MB다. 서버는 확장자, MIME Type, 실제 이미지 디코딩 결과와 실제 포맷의 일치 여부를 모두 검증한다. 새 파일을 먼저 저장하고 DB 변경이 성공한 뒤 기존 파일을 삭제하며, DB 변경 실패 시 새 파일을 보상 삭제한다.

업로드 이미지는 `GET /profile-images/{fileName}`으로 제공한다. UUID와 허용 확장자로 구성된 파일명만 허용하고 정확한 이미지 Content-Type과 `X-Content-Type-Options: nosniff`를 적용한다. DB에는 파일명이 있지만 실제 파일이 없는 경우 헤더와 마이페이지에서 기본 이미지로 대체한다.

프로필 사진 변경·삭제 성공 후 현재 Spring Security 인증 객체의 파일명을 즉시 갱신하여 재로그인 없이 공통 헤더에 반영한다. 기존 권한과 세션은 유지한다. 회원 탈퇴 시에는 기존 정책에 따라 프로필 이미지 DB 값과 실제 파일을 유지한다.

운영 환경의 `/hobbymate`는 Context Path로 적용하며 내부 URL과 DB 저장값에 직접 포함하지 않는다.

# 5. 모임

## 5.1 모임

HobbyMate의 핵심 기능이다.

회원은 원하는 취미의 모임을 직접 생성하거나 기존 모임에 가입하여 활동할 수 있다.

모임은 하나의 독립된 커뮤니티이며

- 가입회원
- 게시판
- 만남
- 운영진

을 가진다.

---

## 5.2 모임 생성

로그인한 ACTIVE·본인인증 완료 회원 중 LEADER인 ACTIVE/BLOCKED 모임이 5개 미만인 회원만 모임을 생성할 수 있다. 화면 진입과 등록 처리에서 같은 조건을 재검증한다.

모임 생성 시 다음 정보를 입력한다.

- 모임명
- 카테고리
- 대표 이미지
- 한줄 소개
- 상세 소개
- 모집 인원
- 모집 여부
- 가입 방식
- 성별 제한
- 연령 제한

세부 입력 기준:

- 모임명: 필수, 앞뒤 공백 제거 후 2~50자
- 활동 지역: 필수, 단일 문자열 최대 200자
- 한줄 소개: 필수, 최대 500자
- 상세 소개: 필수 일반 텍스트, 10~2,000자
- 대표 이미지: 선택, 1장, `jpg/jpeg/png/webp`, 최대 5MB, 권장 16:9
- 연령: 만 18~100세, 최소 연령은 최대 연령 이하
- 최대 정원: 2~1,000명
- 최초 모임 상태: `ACTIVE`
- 최초 모집 상태: 사용자 입력 없이 `OPEN`
- 승인제 가입 안내: 선택, 화면 최대 500자, DB `VARCHAR(1000)`

내부 URL은 `GET /clubs/new`, `POST /clubs`를 사용하며 `/hobbymate`를 직접 붙이지 않는다. 모임과 개설자 `LEADER` 회원 등록은 하나의 트랜잭션으로 처리한다. 개설 성공 후 현재 흐름에 따라 메인으로 이동하고 일회성 성공 메시지를 표시한다.

---

## 5.2.1 공개 모임 상세 조회

- 공개 상세 URL은 `GET /clubs/{clubId}`이며 비회원도 조회할 수 있다.
- 운영 상태가 `ACTIVE`인 모임만 공개한다. 자진 폐쇄, 관리자 폐쇄, 차단·삭제 상태는 동일한 이용 불가 안내와 404 응답으로 처리한다.
- 모집 상태 `OPEN`, `FULL`, `CLOSED`는 운영 상태와 별개이므로 운영 상태가 정상이라면 모두 상세 조회할 수 있다.
- 대표 이미지, 모임명, 카테고리, 지역, 소개, 모임장 닉네임·프로필 이미지, ACTIVE 회원 수, 정원, 모집·가입 방식, 성별·연령 조건, 가입 안내, 생성일·최근 활동일을 표시한다.
- 현재 인원은 `HM_CLUB_MEMBER.MEMBER_STATUS = ACTIVE`인 `LEADER`, `MANAGER`, `MEMBER`만 집계하고 탈퇴·강퇴 회원은 제외한다.
- 로그인 회원의 모임 역할·상태, 승인 대기, 영구 가입 제한, 재가입 제한은 서버의 인증 회원번호로 조회한다. 클라이언트가 회원번호나 역할을 전달하지 않는다.
- 모임 상세와 향후 내부 기능 화면은 `홈`, `공지사항`, `자유게시판`, `만남모집`, `만남후기`, `모임관리` 순서의 공통 가로 메뉴를 사용한다. 화면 메뉴명 `만남모집`, `만남후기`는 내부 게시판 유형 코드 `MEETING`, `REVIEW`와 구분한다. 현재 메뉴는 활성 상태를 표시하며 `모임관리`는 ACTIVE 모임장·운영진에게만 노출한다. 실제 관리 URL은 구현 시 서버에서도 역할을 재검증한다.
- 가입·가입 신청·모임 활동·관리·수정 처리는 후속 기능이다. 상세 화면에서는 관계와 모집 상태에 맞는 안내만 제공하고 존재하지 않는 처리 URL을 만들지 않는다.
- 대표 이미지 또는 모임장 프로필 이미지가 없거나 로드되지 않으면 각각 기존 HobbyMate 기본 이미지와 기본 프로필 이미지를 표시한다.

# 6. 만남

## 6.1 만남

모임은 정기모임 또는 번개모임을 생성할 수 있다.

만남은

- 대면
- 비대면

두 가지 유형을 지원한다.

---

## 6.2 만남 유형

| 유형    | 설명   |
| ------- | ------ |
| OFFLINE | 대면   |
| ONLINE  | 비대면 |

---

## 6.3 대면 만남

대면 만남은

다음 정보를 입력한다.

- 제목
- 날짜
- 시간
- 장소
- 모집 인원
- 참가비
- 내용

장소 입력 시 카카오 지도 또는 네이버 지도 API를 이용하여 장소를 검색한다.

선택한 장소는

- 주소
- 위도
- 경도

를 저장한다.

---

## 6.4 비대면 만남

비대면 만남은 다음 정보를 입력한다.

- 제목
- 날짜
- 시간
- 접속 링크
- 모집 인원
- 내용

Zoom / Google Meet / Discord 등의 링크를 등록할 수 있다.

---

## 6.5 참가 신청

회원은 만남 참가 신청을 할 수 있다.

참가 정원 안의 신청자는 즉시 참가 확정하고, 정원을 초과한 신청자는 신청 순서대로 대기 등록한다.

---

## 6.6 참가 취소

참가자는 만남 시작 10분 전까지 참가를 취소할 수 있다. 시작 10분 전부터는 일반 참가 취소를 허용하지 않는다.

## 7.2 만남 모집 게시판

## 7.6 전체 자유게시판

전체 회원이 자유롭게 이용하는 게시판이다.

## 7.7 건의 게시판

---

## 7.8 신고 게시판

회원은 게시글, 댓글, 회원, 모임 등을 신고할 수 있다.

작성자와 관리자만 조회 가능하다.

게시글 작성 시 최대 25장의 이미지를 업로드할 수 있다.

# 8. 관리자

## 8.1 관리자 페이지

관리자는 관리자 페이지를 통해 서비스 전체를 관리할 수 있다.

관리자는 일반 회원과 구분되는 ADMIN 권한을 가진다.

---

## 8.2 회원 관리

관리자는 다음 기능을 수행할 수 있다.

- 회원 조회
- 회원 검색
- 회원 상세 조회
- 회원 상태 변경
- 회원 이용 정지
- 회원 이용 정지 해제

회원 탈퇴 여부도 확인할 수 있다.

## 8.2.1 본인인증처리(임시)

실제 휴대폰 본인인증 API 연동 전까지 관리자는 일반회원을 임시 본인인증 완료 상태로 처리할 수 있다. 내부 URL은 `GET /admin/member-verifications`이며 화면 조회, 개별·일괄 처리 및 취소는 모두 `ROLE_ADMIN`만 접근할 수 있다. `/hobbymate`는 운영 Context Path로만 적용한다.

상단에는 탈퇴하지 않은 미인증 일반회원 중 인증 방식이 없는 회원을, 하단에는 인증 방식이 정확히 `ADMIN_TEMP`인 인증 완료 일반회원만 표시한다. 실제 인증기관을 통해 인증된 회원은 임시 인증 취소 대상에 포함하지 않는다.

두 목록은 동일한 검색 조건을 사용하되 각각 10건씩 독립적으로 페이징하고 페이지 번호는 5개 단위로 표시한다. 전체선택은 검색 결과 전체가 아닌 각 목록의 현재 페이지에만 적용한다.

개별 처리에서는 이름, 생년월일, 성별, 휴대폰 번호를 확인·수정하고 필수 처리 사유를 입력한다. 일괄 처리는 회원가입 시 저장된 정보를 사용하며, 선택 회원 중 한 명이라도 필수정보가 없거나 현재 상태 조건을 만족하지 않으면 전체를 롤백한다.

임시 인증 완료 시 인증 여부를 `Y`, 인증 방식을 `ADMIN_TEMP`로 저장하고 처리 일시·처리 관리자·사유를 기록한다. 임시 CI는 서버가 `TEMP-{회원번호}-{UUID}` 형식으로 생성한다. 취소 시 인증 관련 값만 초기화하며 이름, 생년월일, 성별, 휴대폰 번호 등 기본 회원정보는 되돌리거나 삭제하지 않는다.

처리와 취소는 현재 상태를 잠금 조회한 뒤 조건부 UPDATE와 관리자 이력 저장을 하나의 트랜잭션으로 수행한다. 이력에는 인증 전후 상태·방식·CI, 개별/일괄 구분과 작업 UUID를 저장하며 CI와 개인정보는 애플리케이션 로그나 관리자 화면에 노출하지 않는다.

## 8.7 카테고리 관리

관리자는 취미 카테고리를 관리한다.

가능한 기능

- 카테고리 목록 및 카테고리별 전체 모임 수 조회
- 카테고리 등록
- 카테고리 수정
- 사용 여부 변경
- 정렬 순서 변경

카테고리는 기존 모임과의 FK 및 과거 데이터 보존을 위해 물리 삭제하지 않는다. 사용 중지한 카테고리는 기존 모임에서 유지되지만 신규 모임 개설 화면에서는 제외한다. 다시 사용 설정하면 서버 재시작 없이 개설 화면에 재노출한다.

카테고리명은 앞뒤 공백을 제거한 뒤 대소문자를 구분하지 않고 중복을 허용하지 않는다. 이름은 2~50자, 관리자용 설명은 최대 200자이며 노출 순서는 1 이상의 정수다. 순서 일괄 저장은 전체 카테고리를 대상으로 하나의 트랜잭션에서 처리하고 입력 순서값 기준으로 1부터 연속된 값으로 정규화한다.

관리 화면은 카테고리명 검색과 사용 중·사용 중지 필터를 제공한다. 사용자 화면에는 `USE_YN = 'Y'`인 최상위 카테고리만 `DISPLAY_ORDER`, `CATEGORY_ID` 순서로 노출한다. 카테고리 계층·이미지·통계·물리 삭제는 이번 기능 범위에 포함하지 않는다.

# 15. 확정 서비스 운영 정책

이 장은 기능 구현 전에 확정한 통합 정책이다. 앞 장의 설명과 충돌하면 이 장을 우선한다. 사용자 화면 용어는 `만남`과 `모임`으로 통일한다.

## 15.1 모임

- 비공개 모임은 운영하지 않는다. ACTIVE 모임의 기본 정보와 상세 소개는 누구나 볼 수 있고, 내부 게시판과 회원 기능은 해당 모임 ACTIVE 회원만 이용한다. `CLOSED`, `BLOCKED` 모임은 일반 검색·목록에서 숨긴다.
- 모임은 `ACTIVE`이면서 본인인증 완료 회원만 개설한다. 회원이 모임장인 `ACTIVE`·`BLOCKED` 모임은 최대 5개이고 `CLOSED`는 제외한다. `HM_CLUB`과 모임장 `HM_CLUB_MEMBER`는 한 트랜잭션으로 생성한다.
- 가입 방식은 `IMMEDIATE`, `APPROVAL`이다. 가입 신청 메시지는 화면 500자, DB `VARCHAR(1000)`이다.
- 승인제 모임의 가입 신청 안내·질문은 선택 입력이며 화면 최대 500자, `HM_CLUB.JOIN_GUIDE VARCHAR(1000)`에 저장한다. 즉시 가입에서는 저장하지 않는다.
- 가입 시 ACTIVE 회원, 본인인증, 모집 `OPEN`, 정원·성별·연령, 기존 ACTIVE 가입·WAITING 신청, 영구 제한, 탈퇴·강퇴 후 12시간 제한을 검사한다.
- 성별은 `MIXED`, `FEMALE`, `MALE`이며 연령은 가입 시점에만 검사한다.
- 정원이 차면 `OPEN → FULL`, 자리가 생기면 `FULL → OPEN`으로 자동 변경한다. `CLOSED`는 모임장의 수동 마감이며 수동으로만 OPEN 복귀하고 현재 인원이 정원 이상이면 복귀할 수 없다.
- 역할은 `LEADER`, `MANAGER`, `MEMBER`이고 운영진은 최대 5명이다. 모임장은 정보·모집·가입·역할·강퇴·위임·폐쇄·콘텐츠·만남을 관리한다. 운영진은 가입, 콘텐츠, 일반 회원 강퇴, 만남을 관리하며 모임장과 다른 운영진은 강퇴할 수 없다.
- 모임 회원 상태는 `ACTIVE`, `LEFT`, `KICKED`이다. 탈퇴·강퇴 콘텐츠는 유지하고 작성자는 `탈퇴한 회원`, `강퇴된 회원`으로 표시하며 프로필 접근을 제한한다.
- 자진 탈퇴와 영구 제한되지 않은 강퇴는 12시간 후 재가입할 수 있다. 가입·탈퇴·강퇴·역할은 `HM_CLUB_MEMBER_HISTORY`, 영구 제한은 `HM_CLUB_BAN`에 보존한다.
- 모임장은 회원이 남아 있어도 폐쇄할 수 있다. 회원은 LEFT, 예정 만남은 취소 처리하고 콘텐츠는 보존한다. 자진·관리자 폐쇄는 `CLOSED_TYPE`으로 구분하며 자진 폐쇄는 30일 이내 복구 가능하다.

## 15.2 만남

- 해당 모임의 ACTIVE 회원은 누구나 만남을 생성한다. 유형은 `OFFLINE`, `ONLINE`, 참가 방식은 `FIRST_COME`만 지원한다.
- 정원은 최소 2명이며 모임 최대 정원을 넘지 않는다. 정원 내 신청자는 즉시 `CONFIRMED`, 초과 신청자는 순서대로 `WAITING`이다.
- 자리가 생겨도 자동 확정하지 않고 1번 대기자에게만 참가 제안을 보낸다. 참가·불참 응답과 만료 일시를 저장하며, 시작 10분 전 미응답 제안은 만료하고 노쇼로 보지 않는다.
- 참가자는 시작 10분 전까지 취소할 수 있다. 생성자·모임장·운영진과 관리자는 정책상 만남을 취소할 수 있다.
- 만남 취소 시 참가자·대기자에게 알리고 연결 모집글을 `CANCELED`로 변경하며 이력을 보존한다.
- 참석과 노쇼를 기록하되 자동 제재하지 않는다. 실제 참석자만 회원·만남당 후기 하나를 작성하며 본인은 수정, 작성자 또는 모임 운영 권한자는 삭제할 수 있다.

## 15.3 게시판·댓글

- 모임 게시판은 `NOTICE`, `FREE`, `MEETING`, `REVIEW`이다.
- NOTICE는 모임장·운영진만 작성하고 중요 공지를 상단 고정하며 회원에게 알린다. FREE는 ACTIVE 회원이 작성한다.
- 모임 공지사항 목록 URL은 `GET /clubs/{clubId}/notices`이며 로그인한 해당 모임 `ACTIVE` 회원만 조회할 수 있다. 미가입·승인 대기·탈퇴·강퇴 회원은 직접 URL로 접근해도 차단하고, 운영 상태가 `ACTIVE`가 아닌 모임은 일반 사용자에게 노출하지 않는다.
- 공지 목록은 해당 `CLUB_ID`, `POST_TYPE = NOTICE`, `POST_STATUS = ACTIVE`, `DELETED_AT IS NULL` 조건으로 조회한다. `NOTICE_YN = Y` 고정 공지를 먼저 정렬하고 그 안에서는 작성일시와 게시글 번호의 최신순으로 정렬한다. 고정 공지는 페이징 결과 안에서 한 번만 노출한다.
- 공지 검색은 제목, 내용, 제목+내용, 작성자 닉네임을 지원하며 검색어는 앞뒤 공백을 제거하고 최대 100자로 제한한다. 목록은 기본 20건이고 20·50·100건을 선택하며 페이지 블록은 5개다. 검색 유형·검색어·페이지 크기는 페이지 이동 시 유지한다.
- 공지 작성 가능 표시는 서버가 조회한 `HM_CLUB_MEMBER`의 `ACTIVE` 상태와 `LEADER`·`MANAGER` 역할을 기준으로 계산한다. 공지 상세·작성·수정·삭제와 알림 발송은 후속 구현 범위다.
- MEETING 글은 만남 생성 시 자동으로 한 개만 생성하고 수정·취소를 동기화한다. REVIEW는 실제 참석자만 작성하고 회원·만남당 한 개로 제한한다.
- 이미지는 최대 25장, 장당 10MB, 글 전체 100MB이며 `jpg`, `jpeg`, `png`, `webp`만 허용한다. 본문 위치·순서·좌우/가운데 정렬을 저장한다.
- 게시글은 공지 상단 후 최신순이며 제목, 내용, 제목+내용, 작성자 닉네임으로 검색한다.
- 댓글은 모임 ACTIVE 회원만 작성하고 작성자만 수정한다. 작성자·모임장·운영진·관리자가 소프트 삭제할 수 있고 `삭제된 댓글입니다.`로 표시한다.
- 답글은 깊이 1, 정렬은 오래된 순이다. 댓글 좋아요는 지원하지 않고 멘션은 v2 후속 범위다.

## 15.4 알림

- 읽음 상태는 `READ`, `UNREAD`이며 개별·전체 읽음을 지원하고 90일 보관한다.
- 댓글·답글·좋아요·모임 공지·만남·모임 관련 수신 설정은 기본 ON이며 특정 모임의 새 만남 알림을 별도 해제할 수 있다.
- 가입 신청·승인·거절, 모임장 위임, 강퇴, 만남 생성·신청·대기·제안·변경·취소·종료, 댓글·답글·좋아요, 공지, 신고 접수·결과를 알린다.
- 대기 제안, 만남 취소·일정 변경, 위임, 강퇴, 신고 결과는 `IMPORTANT`다. 대기 제안 알림은 대상 ID, 액션 상태와 만료 일시를 저장한다.

## 15.5 신고·제재

- 대상은 회원, 모임, 만남, 게시글, 댓글이다.
- 사유는 `SPAM_AD`(스팸·광고), `ABUSE_DEFAMATION`(욕설·비방), `SEXUAL_CONTENT`(선정적 콘텐츠), `HATE_DISCRIMINATION`(혐오·차별), `FRAUD_FALSE_INFORMATION`(사기·허위정보), `ILLEGAL_ACTIVITY`(불법행위), `CLUB_RULE_VIOLATION`(모임 규칙 위반), `OTHER`(기타)이다.
- OTHER 상세 사유는 필수·최대 500자이며 같은 회원의 같은 대상 신고는 1회만 허용한다.
- 상태는 `RECEIVED`, `REVIEWING`, `COMPLETED`, `REJECTED`다. 신고자 정보와 관리자 메모는 피신고자에게 공개하지 않는다.
- 누적 건수만으로 자동 숨김·제재하지 않는다. 관리자는 반려, 경고, 콘텐츠 삭제, 일시·영구 정지, 모임 폐쇄, 만남 취소, 조치 없음을 기록한다.
- 신고자는 접수·처리 여부만 확인한다. 허위·악의적 신고와 신고 제한 기간, 접수·인정·반려·삭제·경고·정지 이력을 구분한다.

## 15.6 관리자

- 권한은 `ADMIN`, `SUPER_ADMIN`이다. ADMIN은 회원·임시 인증·신고·콘텐츠·모임·만남·공지 운영을 수행한다.
- SUPER_ADMIN은 관리자 권한 부여·회수, 운영 로그, 서비스 설정, 영구 정지 해제, 중요 정책을 추가 관리한다.
- 회원 상태는 `ACTIVE`, `SUSPENDED`, `PERMANENT_BANNED`, `WITHDRAWN`이다. 경고·7일/30일/사용자 지정 정지·영구 정지·해제는 별도 이력으로 보존한다.
- 관리자 주요 작업은 처리자, 유형, 대상, 변경 전후, 사유, 시각, IP 등 감사 정보를 보존한다. CI·전화번호·생년월일은 일반 로그에 원문 출력하지 않는다.
- 대시보드는 오늘 가입 회원·모임·만남·게시글, 미처리 신고, 정지 회원, 관리자 폐쇄 모임을 집계할 수 있게 설계한다.

## 15.7 이미지·파일

- 허용 확장자는 `jpg`, `jpeg`, `png`, `webp`다. 프로필은 최대 5MB이며 200×200 썸네일, 모임 대표 이미지는 1장·권장 16:9다.
- 초기 저장소는 로컬이며 구현 시 `StorageService` 아래 `LocalStorageService`, 향후 `S3StorageService`로 교체 가능하게 한다.
- DB에는 물리 절대 경로 대신 저장 제공자, 저장 키·상대 경로, 원본·저장 파일명, 크기, MIME 타입을 관리한다.

## 15.8 검색·정렬·페이징

- 모임은 이름·소개·모임장 닉네임 검색과 지역·카테고리·성별·연령·모집 필터, 최근 활동순을 지원한다.
- 만남은 제목 검색과 날짜·지역·모집·유형 필터, 가까운 일정순을 지원한다. 게시글은 최신순, 댓글은 오래된 순이다.
- 공통 목록은 기본 20개이며 20·50·100개를 선택한다. 신규 관리자 목록도 같은 정책을 적용한다.
- 이미 구현된 `본인인증처리(임시)`는 확정된 기능별 예외로 페이지당 10건·페이지 블록 5개를 유지한다.

## 15.9 차단·즐겨찾기·공개 프로필

- 회원은 자신을 제외한 다른 회원을 중복 없이 차단·해제한다. 차단 콘텐츠는 `차단된 회원의 콘텐츠입니다.`로 접고 필요 시 펼친다.
- 차단은 프로필·개인 알림과 향후 DM·팔로우를 제한하지만 기존 모임 탈퇴나 만남 취소를 자동 처리하지 않는다. 운영상 최소 정보와 운영진 조회는 유지한다.
- 공개 모임은 가입 여부와 관계없이 즐겨찾기할 수 있고 회원·모임 조합은 하나다. 자기 모임도 가능하며 폐쇄 모임은 목록에서 숨기되 관계는 보존한다.
- 공개 프로필은 닉네임, 프로필 이미지, 자기소개, 관심 취미, 공개 허용한 모임·만남·후기다. 아이디·이메일·전화·생년월일 원본·CI·주소·인증·신고·제재·관리자 메모는 비공개다.

## 15.10 탈퇴·개인정보·로그인 이력

- 탈퇴 후 즉시 삭제하지 않고 30일 보관한 뒤 법적·운영상 최소 이력을 제외한 이름·전화·생년월일·성별 등을 삭제 또는 익명화하고 처리 일시를 기록한다.
- CI는 탈퇴 즉시 NULL, 아이디는 보존해 재사용을 금지한다. 닉네임과 이메일은 익명 값으로 변경해 원래 값을 재사용할 수 있다.
- 탈퇴 직후 새 계정 가입은 허용하되 기존 회원은 복구하지 않는다. 콘텐츠는 유지하고 작성자는 `탈퇴한 회원`, 프로필 접근은 제한한다.
- 로그인 성공·실패 이력은 회원, 로그인 아이디, 시각, 성공 여부, IP, User-Agent, 기기·브라우저, 대략적 지역을 저장한다. 회원은 최근 30건, 관리자는 운영에 필요한 추가 보안 정보를 조회한다.

## 15.11 후속 버전

- v2 후속 기능은 댓글 멘션, DM, 팔로우, S3 저장소, 자동 욕설·AI 콘텐츠 필터다.
- 이번 문서·DB 설계 확정 작업에서는 Java, Mapper, HTML, CSS, JavaScript 기능 코드를 구현하지 않는다.
